# 写作边界与定位设计

这份文档不是给读者看的，是给你自己看的。写每一章之前先读一遍。

---

## 一、这本书到底是什么

**它是方法论，不是产品说明书。**

一句话定义：

> 这是一本讲「怎么用游戏的角度过好自己的人生」的方法论。它有一个参考实现，但不是必须的。

### 这个定位为什么成立

因为方法论和工具本来就是可以分离的：

| | 方法论 | 工具 |
|---|---|---|
| 内容 | 目标、规则、反馈、自愿四个要素怎么用 | 同一套机制的自动化版本 |
| 形态 | 这本书 / 纸笔 / 备忘录 | 人生冒险之旅 |
| 价值 | 你自己搭出来的东西才属于你 | 省掉搭建的时间 |
| 依赖关系 | **不依赖工具** | 依赖方法论 |

**关键：读完这本书，你不用任何 App 就能把整套系统搭起来。**

这不是为了显得大方。这是因为：
1. 方法论本身就该能脱离实现独立成立——不然它就不是方法论，是说明书
2. 能自己搭出来的东西，读者才会真的用；用别人的 App，两周后就不打开了
3. 一旦书依赖产品，它就从作品变成了软文

### 反过来也成立

工具本来就是从真实生活里长出来的：

> 这套系统的每一个功能，都是我先在现实生活和工作里遇到问题、然后做出来的。不是我设计了一个系统，然后套到生活上。

这一点是书的可信度来源，也是产品的地基。**两者同源，但不同层。**

## 二、软广是怎么被看出来的（以及怎么不被看出来）

### 会被看出软广的四种写法

| 写法 | 读者的反应 |
|---|---|
| 每章都出现产品名 | 「这是广告」 |
| 机制只在产品里能实现 | 「这是软文」 |
| 讲功能不讲原理 | 「这是功能文档」 |
| 结局是「快来下载」 | 「这是营销」 |
| 用产品术语代替通用词（「追杀」「栖湾群岛」） | 「他在教我他的产品」 |

### 不会被看出软广的写法

| 写法 | 读者的反应 |
|---|---|
| 产品名全书出现 ≤ 2 次（前言一次、最后一句一次） | 「作者做的东西，顺便提了」 |
| 每个机制都有纸笔版本 | 「这真的能用」 |
| 讲原理，然后说「我是这么做的」 | 「这是作者的方法」 |
| 结尾是「这套东西属于你自己」 | 「他没想卖我什么」 |
| 用通用词，产品名只在必要处点明 | 「这是方法论」 |

### 最重要的一条判断

**问自己：把产品名全部删掉，这本书还成立吗？**

- 成立 → 方法论 ✓
- 不成立 → 说明书（软广）✗

这一条就是唯一的测试。

## 三、产品在书里的位置（只有两处）

### 第一处：前言

一句话，说明你为什么写这个，顺便说清你和产品的关系。

参考写法：

> 我确实把自己那套做成了一个 App，但那是我自己的事。书里讲的东西，删掉那个 App 照样成立。

**要点：主动说，不要藏。** 藏着反而显得可疑。主动说明反而建立了信任——因为读者知道你没打算骗他。

### 第二处：最后一句

全书最后一个落点。参考写法：

> 这套系统属于你自己。你可以用纸和笔搭，也可以用我做的那套。区别只在于：一个是你的，一个是我的。

**要点：不写下载链接，不写二维码。** 想找的人会自己搜。写链接的那一刻，整本书的性质就变了。

### 中间 14 章

**产品名 0 次。** 这条不要打折扣。

如果某章写着写着觉得「这里必须提一下产品才能说清」，说明那一章的机制还没抽象干净——回去重写，把机制从实现里剥出来。

## 四、「最小版」是全书的信任锚点

每条机制必须有，而且必须真的能不用 App 实现。

格式固定：

```
- 最小版：<不用 App 怎么实现>
```

写法要求：
- 具体到可以照做。不写「用备忘录记录」，写「在备忘录建一条笔记，标题写今天的日期，里面只写一件事」。
- 你自己试过一遍。没试过就别写。
- 一句话以内。长了说明你没想清楚。

## 五、「跑下来」那一栏的诚实规则

这是你唯一的差异化，也是唯一可能翻车的地方。

| 情况 | 怎么写 |
|---|---|
| 有导出数据 | 数字 + 时间范围 + 口径 |
| 只有截图 | 「截图见附录 X」+ 描述能看到什么 |
| 只有印象 | 「我的印象是……但我没有记录，这一条不算证据」 |
| 完全没观察 | 「还没观察出来」或删掉这一栏 |

**绝对不能做的三件事：**
1. 编数字。哪怕「大约提升 40%」这种模糊表述，没记录就是编。
2. 把印象写成数据。「感觉效率高了」不能写成「效率提升 3 倍」。
3. 事后补记当实时记录用。补记要写明「这是事后回想」。

## 六、理论出处怎么标注

这一章里用到了别人的东西，就得标。不是学术洁癖，是让你自己站得住。

| 内容 | 处理方式 |
|---|---|
| 自我决定理论（Deci & Ryan） | 正文提一句「这是心理学里的」，章末列出处 |
| 心流（Csikszentmihalyi） | 同上 |
| 过度理由效应（Deci, Koestner & Ryan 1999） | **必须标**，因为第 6 章全靠它 |
| 你自己的观察 | 明确写「这是我自己的账本，不是证据」 |

**原则：理论的部分标明来处，观察的部分标明局限。** 这两个标注都不会削弱你，反而会让读者更信你。

## 七、合规红线（必查）

《广告法》第十七条：除医疗、药品、医疗器械广告外，禁止其他任何广告涉及疾病治疗功能，并不得使用医疗用语。

### 禁用词

| 类别 | 禁用表述 |
|---|---|
| 疾病名 + 功效 | 治疗 ADHD / 改善多动症 / 缓解拖延症 |
| 医疗行为 | 干预 / 疗程 / 康复 / 治愈 / 症状改善 |
| 效果承诺 | 专治 / 一定有效 / 三天见效 / 彻底解决 |
| 诊断替代 | 帮你判断是不是 ADHD / 自测 ADHD |

### 可用表述

| ✅ 可以 | ❌ 不可以 |
|---|---|
| 我是个注意力很难集中的人 | 专为 ADHD 设计 |
| 给「打开任务就发呆」的人 | 改善注意力涣散 |
| 我总是计划做得很漂亮，执行在明天 | 治疗拖延症 |

**判断标准：句子的主语是「我」还是「产品」。**
- 主语是「我」→ 个人经历陈述，安全
- 主语是「产品」+ 效果动词 → 疗效宣称，违规

## 八、每章写完的自检

- [ ] 把产品名删掉，这一章还成立吗？
- [ ] 最小版我试过吗？
- [ ] 跑下来的数字是真的吗？
- [ ] 有没有禁用词？
- [ ] 有没有「你应该」「只要……就能」？
- [ ] 开篇是不是一个具体时刻，不是「很多人」？
- [ ] 用到的理论标出处了吗？
- [ ] 一个完全不知道我产品的人，读这章能用起来吗？

八条全过才发。

## 九、连载时的转化埋点（小红书 / 公众号）

**书里不推产品，笔记里可以。** 位置不同，容忍度不同。

| 位置 | 内容 | 产品出现方式 |
|---|---|---|
| 书正文（1–14 章） | 机制 + 最小版 + 真实数据 | 0 次 |
| 小红书笔记正文 | 同章精简版（800 字内） | 0 次 |
| 小红书笔记结尾 | 「这套东西我用一个 App 在跑」 | 1 次，一行 |
| 小红书评论区 | 有人问再答 | 自然回答 |
| 公众号长文 | 章 + 截图 | 文末一次 |

**为什么笔记里可以提：** 笔记是内容平台的常态，读者预期看到作者自己的东西；书是作品，读者预期它是纯粹的。

## 十、上线节奏

| 阶段 | 时间 | 动作 | 判据 |
|---|---|---|---|
| 验证 | 第 1–2 周 | 写第 6 章（反例章），拆成 3 篇笔记 | 有没有人问「这是什么 App」 |
| 连载 | 第 3–12 周 | 每周 1 章，小红书 + 公众号 | 有没有 3 篇以上收藏过千 |
| 结集 | 第 13–16 周 | 仓库 + 在线页 + EPUB/PDF | Star 数 |
| 判断 | 第 17 周 | 看数据决定是否找出版方 | Star 过 2000 或 3 篇收藏过千 |

**注意：验证期建议先发第 6 章，不是第 1 章。** 因为第 6 章是全书最锋利的部分——「为什么大多数游戏化都会失效」这个角度新颖、有反常识、而且天然避开了「推销」的嫌疑（因为它在讲别人的失败）。

达不到判据就停在这里。免费版继续做，它已经是最好的获客资产了。
